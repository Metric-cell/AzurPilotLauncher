**行为变化**

- 第 1 项进程清理保护已完整撤回：启动前恢复按配置端口清理占用进程并等待释放；恢复原有进程组终止行为和 `Drop` 按 `ALAS_LAUNCHER_PID` 扫描的兜底清理。启动取消和 HTTP(S) 就绪检查仍保留。
- 开发工作树、未提交/未跟踪文件、本地提交领先或分叉、分支不匹配均会停止发布更新。检查贯穿工具准备和 Git 重试，并在 Python 更新及 `reset --hard` 前再次核对。开发模式和 `--skip-update` 保留部署配置与 `uv.lock`，依赖使用冻结同步；正常发行目录保留镜像路线，同步后恢复发行锁文件。
- 启动画面通过 `splash_ready` IPC 确认页面已注册更新回调，缓存并重放最新进度。错误预览显示模拟失败和 42%，不会停在初始 4%。关闭启动窗口会请求取消并等待工作停止；普通失败后关闭直接退出，保留已有 `.venv` 与缓存。自动超时重建仅用于普通、非 TLS 的发行环境。
- 后端启动、免密请求、页面导航、连接重试和旧版事件流使用同一份 HTTP/HTTPS 配置，支持 IPv6 与通配监听地址。证书验证失败立即报告具体原因；请求保留证书链及主机名验证。一次性免密令牌按 URL query 编码，日志剔除 query/fragment。
- 旧 SSE 接口必须返回 `text/event-stream`。404/405/501 或 SPA 的 HTML 回退会停止该订阅，不再把 HTML 当作事件流反复连接。控制结果回报有超时且检查 HTTP 状态，重连退避可取消。
- 启动器自更新尊重代理环境变量。仅当更新源连接失败、超时或返回服务端错误，且已存在完整启动器与本地 Python 后端时，允许继续启动；坏清单、无效载荷或 SHA-256 失败仍报错，迷你版仍要求完成安装。
- Linux 无托盘，关闭主窗口会退出；隐藏操作改为普通最小化，忽略 `--start-minimized`，保留可恢复的窗口。Windows/macOS 托盘行为保留。

Rustls 使用锁文件中已有的版本，未升级依赖版本；直接引用用于识别真实证书错误类型。`sysinfo` 已恢复为运行时依赖，用于端口占用进程和环境标记进程的清理。

**仍需处理的兼容范围**

当前 AzurPilot WebSocket 后端未提供旧桌面通知和系统自启控制接口；本次让启动器停止无效订阅，没有把账号任务的 `startup.set` 错接成操作系统自启。要恢复这些桌面集成，需要后端提供对应能力。

Rust HTTP 客户端读取配置证书作为额外信任根；Tauri WebView 仍使用系统证书信任。使用自签名 HTTPS 时须另行配置系统信任，并确保证书包含所访问的主机名，不能仅凭 Rust 请求成功判断页面可显示。

Windows/macOS 窗口、托盘、UAC 与登录自启尚未实机验收。Windows manifest 仍要求管理员权限，Run 注册项不能据此承诺静默提权启动。发布归档首次 Git 初始化失败后留下未完成的 `.git`，下一次启动会保守保护该目录，需要确认其状态后恢复安装。
